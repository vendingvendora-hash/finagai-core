# ADR-040: Operations: backups, daily maintenance, preflight, simulation, one-click readiness

- **Date:** 2026-10-01 · **Status:** decided · **Category:** reversible technical choices (M6/M8 work done ahead of provisioning)

1. **Backups run in GitHub Actions**, not on the Render scheduler: nightly encrypted logical export (AES-256-GCM, key in a GitHub secret and kept offline by Julian), stored as a workflow artifact for 90 days at GitHub, a separate vendor from Neon and Render, with no additional account. Neon's 7-day point-in-time restore remains the first line. Exports carry every value in its exact SQL text form plus per-table checksums; restore runs as the migration role into a freshly migrated database in one transaction (suspends user triggers and foreign keys, loads, restores the event sequence, re-validates every foreign key, verifies every checksum). A monthly `restore-drill` workflow restores the latest backup and runs the full protection suite on it (acceptance A6). The drill found and fixed one defect: events stored a JSON `null` instead of SQL NULL for absent values.
2. **Daily maintenance** (03:00 New York) replaces the separate backup and staleness jobs: it expires overdue governance requests and replays budget-deferred captures. Staleness, retention eligibility (ADR-022), and unresolved deliveries are derived by J3 on every review.
3. **Startup preflight:** in production the server refuses to start if it is not connected as `finagai_app`, if the role can DELETE, or if the applied migrations differ from the repository. Identity-provider reachability is a warning. `scripts/verify-startup.sh` proves all three refusals against the built server in CI.
4. **Deployment manifest fix:** `NODE_ENV=production` makes `npm ci` skip dev dependencies, which would have broken the TypeScript build on the first Render deploy; builds use `npm ci --include=dev`. A unit test checks `render.yaml` against the configuration schema.
5. **Observability:** a JSON access log records method, path, status, and duration, never query strings (approval links carry single-use nonces). A job that fails its final attempt emails Julian once per slot.
6. **Full-system simulation** (`test/integration/system.test.ts`): SDK MCP client over HTTP, Core, J2 and J3 through the real metered model client and budget ledger, governance with OIDC and WebAuthn, scheduler dispatch with real handlers, the real Resend adapter against a fake Resend API, and the audit log. It injects every failure on Julian's list and ends with a synthetic cold start through approved promotion and a baseline review.
7. **One-click readiness:** after provisioning, the `readiness` workflow runs the deployed-service smoke test (Gate 3, automatable part), production database protections (Gate 4), and the real-model J2 (Gate 1) and J3 evaluations, then uploads one report.
8. **Approval-page sign-in** is a WorkOS Connect OAuth application (confidential), verified against WorkOS documentation: its own client ID and secret, redirect URI `<base>/approve/callback`, discovery from the AuthKit domain.
